System Analysis Report

System Architecture & Technology Stack

The PERT-CPM Solver is structured as a lightweight full-stack Python web application running on a Flask web server, with graph theory logic computed asynchronously via NetworkX and data visualizations rendered on the fly with Matplotlib.

Backend Technologies:
  • Flask: Serves routes and exposes the /solve POST API endpoint.
  • NetworkX: Constructs Directed Acyclic Graphs (DAGs), performs topological sorting, cycle detection, predecessor mapping, and successor lookup.
  • Matplotlib & NumPy: Generates sequence flow diagrams using headless layout rendering (matplotlib.use('Agg')).
Frontend Technologies:
  • HTML5 / Vanilla CSS3: Built on semantic structures and modern CSS custom variables (CSS variables) supporting on-the-fly theme switching.
  • Asynchronous Javascript: Collects row entries, performs local validation, posts JSON payloads, and handles DOM manipulation for stats, results, and network graphics.

Core Scheduling & Mathematical Formulations

The solver utilizes standard Critical Path Method (CPM) and PERT calculations for backward/forward passes on project nodes:

  • Expected Duration ($T_E$): Probabilistic activity duration from optimistic ($a$), most likely ($m$), and pessimistic ($b$) times.
    TE = (a + 4m + b) / 6
  • Early Start ($ES$): The earliest time an activity can begin.
    ES(i) = max( EF(p) ) for all predecessors p
  • Early Finish ($EF$): The earliest time an activity can complete.
    EF(i) = ES(i) + TE(i)
  • Late Finish ($LF$): The latest time an activity can finish without delaying the project.
    LF(i) = min( LS(s) ) for all successors s
  • Late Start ($LS$): The latest time an activity can start without delaying the project.
    LS(i) = LF(i) - TE(i)
  • Total Float ($TF$): The buffer time available before project delay.
    TF(i) = LF(i) - EF(i) = LS(i) - ES(i)
  • Free Float ($FF$): The buffer time available without delaying any successor start.
    FF(i) = min( ES(s) ) - EF(i)
  • Activity Variance ($\sigma^2$): Measure of duration uncertainty.
    $\sigma^2 = ((b - a) / 6)^2$
  • Project Standard Deviation ($\sigma_P$):
    $\sigma_P = \sqrt{\sum \sigma^2 \text{ (on critical chain)}}$
  • Probability Z-Score ($Z$): Target date ($D$) evaluation.
    $Z = (D - T_E) / \sigma_P$

UI/UX & Design Architecture

The application is styled with a premium glassmorphism command-center aesthetic, featuring dynamic styling variations across both themes and panels.

Aesthetic Elements:
  • Theme Variations: Midnight Slate (default), Cyberpunk Neon, Nordic Snow (light), and Warm Sunset (light).
  • Dynamic Collapsible Sidebar: An overlay drawer that starts collapsed to prioritize workspace width. Clicking the toggle pulls out a gorgeous metallic panel.
  • Theme-Synced Sidebar CSS Variables: The sidebar background, margins, widget cards, and buttons transition dynamically in real-time between Slate, Neon, Nordic, and Sunset colors.
  • Live Location & Weather Integration: Integrated with standard HTML5 Geolocation API, reverse-geocoded dynamically via OpenStreetMap Nominatim, and updated in real-time using live WMO codes from Open-Meteo.

Probabilistic Capabilities (PERT)

The application fully supports advanced probabilistic analytics that standard CPM lacks. By leveraging statistical modeling, it dynamically assesses project completion uncertainties:

Implemented Analytic Elements:
  • Activity Variance ($\sigma^2$): Computed individually for each node to track estimation uncertainty.
  • Project Standard Deviation ($\sigma_P$): Extracted by tracing a unified critical chain to determine total systemic risk.
  • Interactive Completion Probability: A fluid graphical interface evaluating target completion dates ($D$) utilizing high-precision JavaScript normal-curve CDF algorithms.
